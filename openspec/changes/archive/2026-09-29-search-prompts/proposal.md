## Why

现在只能按原文里连续出现的一整段字句找回提示词。用户记得的往往是几个分开的词，或者是和原文用词不同的说法。收录之后先把关键词、气质词和向量备好，搜索才能按这些线索找回，并在原文里标出为什么命中。

## What Changes

- 保存和改正提示词时，原文仍然立刻、原样入库。后台再为这条提示词准备关键词、气质词和向量。后台没完成或失败时，原文仍可按字面查找。
- 气质词只收风格、媒介、构图、光线、体裁，保留原文写法，并把同一意思的不同写法归在一起。只属于这一条的场景细节留在关键词里。分辨率、时长、帧率这类交付规格不进入气质词。
- 搜索改为：空白查询仍是整库列表；有内容时按空格切开，每一段都要落在同一条的原文、关键词或气质词的任一写法上，才算字面命中。字面结果仍按收录顺序。示例链接不参与。
- 一条字面命中都没有时，用查询去比这条提示词的各段、各关键词、各气质词向量，取最高分。过最低相近线的少数几条显示为「意思相近」。没算好或没有过线的，显示「没有匹配」。字面已有命中时，不再附「意思相近」。
- 命中处在原文中高亮。列表摘要改到包含第一处高亮；打开全文后标出全部命中。从没有搜索词的列表打开时不高亮。
- 改正原文后重算派生物；删除提示词时派生物一起删除。
- 抽词和嵌入都调用 OpenAI 兼容接口。两边各自有 base URL、API key 和 model，写在本地配置文件里，不从环境变量读取。base URL 默认 `https://openrouter.ai/api/v1`，API key 和 model 必须自行填写，没有默认模型。某一边缺 API key 或 model 时，不发送那一边的请求，也不因此把提示词记为失败。
- 处理失败的提示词集中在一页：摘要、失败原因和发生时间。可以从这一页重跑一条或全部。重跑开始后离开该页；再次失败会回来，成功则不再出现。库列表只在存在失败项时链到这一页。
- 本变更不起草新提示词，也不把草稿放进搜索结果。

## Capabilities

### New Capabilities

- `prompt-derivation`: 收录或改正原文之后，在后台保存关键词、气质词和向量，且不改写原文。抽词和嵌入的端点从本地配置文件读取。处理失败的提示词可以集中查看并重跑。

### Modified Capabilities

- `prompt-library`: 搜索不再只按原文中的连续字句；列表摘要和全文要能标出本次搜索的命中处。

## Impact

- 提示词库的 SQLite 数据增加派生物，原文和示例链接的保存规则不变。
- 列表、全文和搜索结果的展示会变。
- 抽词和嵌入都从本地配置文件读取 base URL、API key 和 model。抽词把原文送到配置的对话接口，嵌入把待算文本送到配置的嵌入接口。两边都不发送示例链接。
- 新增一页列出处理失败的提示词，并提供重跑。
- 最低相近线和「意思相近」的条数上限写在同一份配置文件里，不在本提案里写成固定数字。
