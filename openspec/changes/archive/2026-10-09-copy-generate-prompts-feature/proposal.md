## Why

列表和详情只能阅读提示词，不能把全文一次放进剪贴板，列表也不显示收录日期。要写一条新提示词时，只能手贴，不能按这次要写的内容，参照库里已有提示词的写法先生成一份草稿。

## What Changes

- 未筛选列表、字面搜索结果和「意思相近」的每一条，以及详情页，都提供复制。复制的是库存全文，不是摘要，也不带示例链接。
- 上述列表条目显示添加日期。日期是 `created_at` 换到北京时间后的日历日。改正原文不改变这个日期，也不改变列表顺序。详情页不新增日期。
- 新增「写一条」。用户写下这次要写的内容；系统把需求整句嵌入，按相似度取出最多 3 条已有全文当写法范例，再让写作模型生成一份提示词正文。
- 新稿的题材以用户这次的输入为准。范例只提供写法，不把范例的题材写进新稿。
- 生成结果放进现有的「贴上一条」编辑框，示例链接为空。用户改完并保存后，才按现有规则入库并派生。生成本身不入库，需求也不保存。离开或刷新未保存的草稿即丢。
- 没有够格的范例、嵌入未配置或嵌入失败时，仍然按用户输入生成，并说明这次没有参考。写作模型未配置、需求为空、模型失败或返回空白时，不打开保存页，也不发无效请求。
- 搜索规则、派生规则和保存规则不变。本机 Go 服务与 Cloudflare Worker 行为一致。线上仍是现有的公开读写，不新增登录。

## Capabilities

### New Capabilities

- `prompt-drafting`: 按用户这次要写的内容，参照最多 3 条最相近的已有提示词写法，生成一份未保存的草稿，并放进「贴上一条」。

### Modified Capabilities

- `prompt-library`: 列表条目显示添加日期，并在列表和详情提供全文复制。

## Impact

- 本机页面模板和 `internal/web` 的列表、详情增加复制与日期。Cloudflare Worker 的对应页面做同样的展示。
- 页头增加「写一条」。生成使用新的对话配置，检索复用现有嵌入和向量。选范例时按相似度取最多 3 条，字面也能命中的提示词仍可入选，并且不用短查询的更高门槛。
- `./data/config.json` 与 Worker Secret `APP_CONFIG` 增加写作端点 `draft`。缺 API key 或 model 时不调用写作模型。README 说明这一字段。
- 复制需要一段同源静态脚本。Cloudflare 现有 CSP 不允许脚本，要放行这段脚本，同时提示词正文仍然只作为文字展示。
- 不改 `prompts` 表，不保存需求，不给提示词增加「生成而来」的标记。
